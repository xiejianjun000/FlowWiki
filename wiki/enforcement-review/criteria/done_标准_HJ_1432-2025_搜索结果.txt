二、发布背景
===============================================================================

HJ 1432-2025 是生态环境部2025年第41号公告发布的3项国家生态环境标准之一。
该3项标准同期发布，共同构建生态环境分区管控技术标准体系：

  (1) HJ 1430-2025《生态环境分区管控技术指南 总纲》
  (2) HJ 1431-2025《生态环境分区管控信息平台建设指南》
  (3) HJ 1432-2025《生态环境分区管控信息平台接口规范》   <-- 本标准

标准实施后，《"生态保护红线、环境质量底线、资源利用上线和环境准入负面清单"
编制技术指南（试行）》（环办环评〔2017〕99号）即行废止。

三、适用范围
===============================================================================

本标准规定了生态环境分区管控信息平台接口的设计原则、基本要求、类型与内容、
应用模式与使用要求。

本标准适用于：
- 国家和地方生态环境分区管控信息平台应用程序接口（API）的设计与建设
- 指导生态环境分区管控相关业务数据的在线交换、互操作与协同共享

其他业务管理及政务服务平台接口开发可参照执行。

五、术语和定义
===============================================================================

HJ/T 416 界定的以及下列7个术语和定义适用于本标准：

1. 生态环境分区管控
   - 以保障生态功能和改善环境质量为目标，实施分区域差异化精准管控的环境
     管理制度。

2. 生态环境分区管控信息平台
   - 面向生态环境分区管控管理和应用需求，实现生态环境分区管控成果等数据
     的汇交、管理、共享及应用服务的软硬件系统。

3. 接口
   - 信息系统为其他使用方提供数据交换的一种方式，是由一系列功能封装后可
     被信息系统用户直接远程调用的软件接口。

4. 安全验证接口
   - 用户身份验证的应用开发规范性约定，用于安全访问生态环境分区管控信息
     平台提供的相关数据服务接口。

5. 结构化数据接口
   - 根据关键字、空间位置等条件获取生态环境分区管控成果数据的列表清单、
     管控要求以及统计分析等结构化数据的应用开发规范性约定。

6. 文件数据接口
   - 推送及下载生态环境分区管控成果文件、支撑文件以及文件元数据等信息的
     应用开发规范性约定。

7. 空间地图服务接口
   - 提供生态环境分区管控成果数据等相关地图服务访问的应用开发规范性约定。

七、设计原则（第5章）
===============================================================================

标准确立了以下4条设计原则：

5.1 规范性
  接口应在接口命名、字符编码、文本描述、数据交换格式等方面保持统一，
  确保接口可查找、可访问、可理解及可互操作。

5.2 完整性
  接口应保证业务操作的原子性，以确保数据的完整性和一致性。

5.3 安全性
  接口应保证传输对象的信息隐私，宜对传输对象采用转换、加密或验证等
  方式进行传输。

5.4 可扩展性
  接口可根据业务和技术发展需求，进行接口及其功能的扩展。

===============================================================================
八、基本要求（第6章）
===============================================================================

8.1 规范性要求
  - 接口名称：采用骆驼式命名法（CamelCase）
  - 字符编码：UTF-8 字符集
  - 数据交换格式：JSON 格式

8.2 安全性要求
  - 接口应支持 HTTP/HTTPS 协议
  - 安全验证、结构化数据、文件数据接口均应使用 POST 方式请求
  - 接口调用必须提供访问令牌（token）
  - 令牌（token）需设置有效时限，标准规定令牌有效期为 120 分钟
  - 超时未请求接口，需重新登录获取新令牌
  - 敏感数据需脱敏处理
  - 密码信息应采用不低于 SM1 等级的加密技术传输
  - 令牌（token）放入请求头（Header）
  - 请求需携带用户身份凭证（appKey）

8.3 完整性要求
  - 每类接口只完成一类数据处理
  - 保证业务操作的原子性

8.4 运行环境要求（注：来源于建设指南或相关解读）
  - 优先使用生态环境业务专网
  - 硬件符合自主安全可控要求
  - 优先采用云服务环境

九、接口类型与内容（第7章）
===============================================================================

标准将平台接口分为四大类：

┌──────────────────────┬────────────────────────────────────────────────────────┐
│ 接口类型              │ 功能说明                                              │
├──────────────────────┼────────────────────────────────────────────────────────┤
│ 1. 安全验证接口       │ 用户身份验证，通过用户名和密码获取加密令牌（token）     │
│                       │ 及用户身份凭证（appKey），实现API安全访问               │
├──────────────────────┼────────────────────────────────────────────────────────┤
│ 2. 结构化数据接口     │ 根据关键字、空间位置等条件获取生态环境分区管控成果数据    │
│                       │ 的列表清单、管控要求以及统计分析等结构化数据            │
├──────────────────────┼────────────────────────────────────────────────────────┤
│ 3. 文件数据接口       │ 推送及下载生态环境分区管控成果文件、支撑文件以及        │
│                       │ 文件元数据等信息（非结构化/半结构化文件）              │
├──────────────────────┼────────────────────────────────────────────────────────┤
│ 4. 空间地图服务接口   │ 提供生态环境分区管控成果数据等相关地图服务访问          │
│                       │ 支持 WMTS / WMS / WFS 三种标准协议                    │
└──────────────────────┴────────────────────────────────────────────────────────┘

每个接口由以下四部分组成：
  - 接口地址（URL）
  - 请求参数（Request Parameters）
  - 请求方式（Request Method）
  - 响应参数（Response Parameters）

十、四类接口详细技术内容（第7章）
===============================================================================

10.1 安全验证接口
  - 功能描述：用户身份验证的应用开发规范性约定，用于安全访问生态环境分区
    管控信息平台提供的相关数据服务接口。
  - 核心流程：用户名+密码 → SM1加密传输 → 获取 token（有效期120分钟）+ appKey
  - 请求方式：POST
  - token 放入请求头（Header）
  - 密码加密等级：不低于 SM1
  - token 有效期：120分钟
  - 超时处理：超时未请求需重新登录获取新token

10.2 结构化数据接口
  - 功能描述：根据关键字、空间位置等条件获取生态环境分区管控成果数据的
    列表清单、管控要求以及统计分析等结构化数据。
  - 请求方式：POST
  - 认证方式：token 放入请求头，带 appKey
  - 包含子接口：
    (a) 获取生态环境分区管控成果数据列表接口
    (b) 根据编码查询管控要求详情接口（精确检索）
    (c) 根据空间位置查询管控要求详情接口（采用 CGCS2000 坐标系经纬度）

10.3 文件数据接口
  - 功能描述：推送及下载生态环境分区管控成果文件、支撑文件以及文件元数据
    等信息。
  - 请求方式：POST
  - 包含子接口：
    (a) 文件推送接口（上传非结构化/半结构化文件）
        - 上传文件类型：成果矢量文件、研究报告、图集等
    (b) 文件下载接口（按行政区划代码 + 文件类型编码查询）
        - 支持按行政区划和文件类型编码进行检索下载
  - 文件类型字典：覆盖成果矢量数据、研究报告等 11 类文件

10.4 空间地图服务接口
  - 功能描述：提供生态环境分区管控成果数据等相关地图服务访问。
  - 支持请求方式：GET / POST
  - 支持的三种标准协议：

  (a) WMTS（Web Map Tile Service / 网络地图切片服务）
      - 获取地图瓦片（Tile）
      - 获取切片元数据（GetCapabilities）
      - 主要操作：
        - GetCapabilities — 获取服务元数据（支持图层、瓦片集、主题集信息）
        - GetTile — 获取数据瓦片（指定图层、瓦片矩阵、行列号、格式）
        - GetPixel — 获取指定坐标位置的像素值（返回JSON格式）
        - SetColors — 设置栅格数据的配色表
        - GetColors — 获取服务的颜色表配置信息
      - GetTile 请求参数示例（资料性）：
        - REQUEST = "GetTile"（必选）
        - SERVICE = "WMTS"（必选）
        - LAYER（必选）— 查询的图层名称
        - TILEMATRIXSET（必选）— 瓦片矩阵集
        - TILEMATRIX（必选）— 瓦片矩阵
        - TILEROW（必选）— 瓦片行号（从上到下 0,1,2...）
        - TILECOL（必选）— 瓦片列号（从左到右 0,1,2...）
        - FORMAT（必选）— 图片格式：image/png / image/jpg / image/webp
        - VERSION（必选）— 服务版本号

  (b) WMS（Web Map Service / 网络地图服务）
      - 获取动态地图
      - 获取地理要素信息
      - 引用标准：GB/T 25597

  (c) WFS（Web Feature Service / 网络要素服务）
      - 获取地理要素矢量数据
      - 引用标准：GB/T 30169
