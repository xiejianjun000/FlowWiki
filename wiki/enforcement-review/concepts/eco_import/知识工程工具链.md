# 知识工程工具链

> 知识工程工具链（Knowledge Engineering Toolchain）是指将原始信息（书籍、政策文件、标准公告）转化为结构化、可检索、互联的知识库所依赖的一套自动化系统和规范化流程。本文档从方法论角度阐述其设计原则与工作模式，而非具体工具操作手册。

---

## 核心理念

### 采集-加工-编译 三层管道

> 该管道概念源自软件工程的数据管道（Data Pipeline）模式，应用于知识管理领域。三层对应知识从原始数据到结构化知识的完整生命周期，每层有明确的输入输出边界。

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  采集层        │ → │  加工层        │ → │  编译层        │
│              │    │              │    │              │
│ ● 爬虫/API    │    │ ● OCR 识别    │    │ ● 模板映射     │
│ ● 微信读书导出 │    │ ● 数据清洗    │    │ ● 概念提炼     │
│ ● 浏览器自动化 │    │ ● 关系构建    │    │ ● 交叉链接     │
│ ● RSS/监控    │    │ ● 格式统一    │    │ ● 质量审计     │
└──────────────┘    └──────────────┘    └──────────────┘
      │                    │                    │
      ▼                    ▼                    ▼
  raw/                raw/processed/        wiki/
  (原始素材)           (已处理源文件)       (知识页面)
```

**设计原则：** 三个目录对应三个生命周期阶段，素材不跨阶段跳跃。处理完成的原始文件移至 `raw/processed/` 存档，wiki 层只保留提炼后的知识页面。

### 为何需要工具链

生态环境政策领域的信息特征决定了手工处理不可行：

| 特征 | 规模 | 应对策略 |
|------|------|---------|
| 标准发布公告 | 每年数十至上百条 | 爬虫自动抓取 + 回溯补全 |
| 地方标准 | 1,900+ 条 | 各省爬虫并行采集 |
| 书籍图文 | 300-700 页/本 | Canvas Hook 逐页导出 |
| PDF 扫描件 | 大量历史文件 | 批量 OCR 识别 |
| 交叉引用关系 | 数千条 | 关系构建器自动生成（build_relations.py） |
| 爬虫日志 | 5 个日志文件 | 记录每次爬虫运行的详细输出 |
| 运维脚本 | 8 个基础设施脚本 | 目录重建、链接优化、文件名修复、vault 迁移

## 采集策略

### 主动采集 vs 被动推送

- **主动采集（Pull）：** 按需运行爬虫抓取生态环境部官网、国家标准平台等定时更新的公开数据源
- **被动推送（Push）：** weread-exporter 的微信读书导出、AI 监控（GitHub/Tavily/arXiv）的新内容发现

### 增量更新

- 爬虫记录已抓取文件的哈希值，避免重复下载
- weread-exporter 自动续传：中途中断后重开浏览器，从上次章节继续
- 图片下载可重复运行，已有文件自动跳过

### 容错设计

- 翻页卡住自动重试：weread-exporter 检测翻页超时后重启浏览器
- 网络抖动容错：urllib 强制 IPv4 避免 macOS IPv6 路由超时
- 分批处理：8 线程并发下载控制资源占用

## 加工方法

### 从 PDF 到 Markdown

```
PDF 文件 → pdfplumber 文本提取 → 有文本? → 写入 .md
                                      ↓ 无文本
                                OCR (pdf2image + Tesseract)
                                      ↓
                                识别文本写入 .md
```

### 关系构建策略

`build_relations.py` 通过以下策略自动建立双向链接：

1. **标准编号匹配**（HJ 1019-2019 → 对应公告文件）
2. **标签继承**（同标签文件互相关联）
3. **父子关系**（公告 → 所含标准）
4. **关键词共现**（高频技术术语关联）

### 监测标准回溯补录策略

监测标准的知识覆盖存在时间断层——2000-2012 年的历史标准散落在各标准文本目录中，未被纳入专门的监测标准目录。`backfill_monitoring_2000_2012.py` 通过以下策略解决：

1. **关键词匹配：** 扫描文件名中包含"测定""监测""检测""采样""分析方法"等 11 个监测类关键词
2. **标准号年份过滤：** 提取标准号中的年份字段，只处理 2000-2012 年区间
3. **去重校验：** 检查目标目录中是否已存在相同标准号，避免重复复制
4. **自动复制归档：** 将符合条件的标准文件复制到监测标准目录，并更新索引

此外，`extract_monitoring_from_bzfb.py` 从标准发布公告中提取监测标准候选（83 条），覆盖水质、大气、土壤、辐射、生态遥感等全部监测子领域，用于补充前瞻性的标准条目。

### 爬虫系统架构

爬虫套件遵循**栏目-页面-字段**三层抽象模式：

1. **栏目层（Section）：** 每个 MEE 栏目（标准发布、标准文本、标准解读等）对应一个爬虫脚本
2. **页面层（Page）：** 每页列表解析为公告/标准条目的标题、链接、发布日期
3. **字段层（Field）：** 详情页提取结构化字段（标准号、发布机构、生效日期、PDF 链接）

关键设计决策：
- **延迟控制：** 请求间隔 1-1.5 秒，避免对 MEE 官网造成压力
- **哈希去重：** 已抓取文件通过内容哈希值判断，避免重复下载
- **沙盒输出：** 各爬虫写入独立的目录树，不发生文件冲突
- **渐进增强：** 先抓取当前页列表，再逐页翻页，支持断点续传

地方标准爬虫采用额外策略应对各省平台差异：
- **nodriver 无头浏览器：** 用于需要 JavaScript 渲染的省级平台
- **URL 模式适配：** 各省市场监管局或生态环境厅的 URL 结构不同，每省脚本独立适配
- **备案索引统一：** 所有地方标准爬虫结果汇集到统一的备案索引文件中

### 模板驱动的一致性

笔记模板通过 YAML frontmatter 确保所有页面具有统一的结构化元数据，使自动处理（关系构建、链接优化、索引生成）可依赖确定字段。

## 编译产出

### 知识分层

| 层 | 目录 | 内容 | 来源工具 |
|----|------|------|---------|
| 原始数据 | `raw/` | 书籍导出、政策 PDF、公告全文 | weread-exporter, 爬虫 |
| 来源索引 | `wiki/source/` | 书籍摘要、来源概览 | 手动 + 模板 |
| 核心概念 | `wiki/concept/` | 跨来源提炼的知识点 | 概念提炼 |
| 标准体系 | `wiki/standard/` | 标准分类全景 | 标准筛选工具 |
| 专题研究 | `wiki/topic/` | 深度分析报告 | AI 监控 + 手动 |
| 法律实体 | `wiki/law/` | 法律条文 + entity 页 | 政策法规模板 |
| 场景入口 | `00_首页/` | 按角色/任务的导航入口 | MOC 模板 |
| 工具目录 | `raw/tool/` | 爬虫、数据处理、知识库基建脚本 | 40 个 Python 脚本 |

### 工具链自身的管理

工具链本身的文档分为三层：

- `raw/tool/` — 工具源码和运行环境（活的，不动）
- `raw/processed/tool/` — 已编译的工具文档镜像（存档，参考）
- `wiki/source/知识库工具链概览` — 工具生态全景索引（导航入口）
